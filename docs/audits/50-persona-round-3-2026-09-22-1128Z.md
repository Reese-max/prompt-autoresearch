## New independent actionable finding

### #12 — P1 BUG — local UI mutation endpoints are not protected by a local-only/auth trust boundary

Issue: https://github.com/Reese-max/prompt-autoresearch/issues/12

Fingerprint:

`prompt-autoresearch + run_app.py local UI server + wildcard interface bind + unauthenticated permissive-CORS mutation endpoints + remote peer can start evolution/final/provider-proxy work`

Current source exposes a reachable causal chain:

1. `run_app.py` allows `GET, POST, OPTIONS` from `Access-Control-Allow-Origin: *`, and `/api/run-evolution` starts `auto_evolve.py` via `subprocess.Popen(..., env=os.environ.copy())`; `/api/run-final` likewise starts the evaluator. Commit-fixed source: https://github.com/Reese-max/prompt-autoresearch/blob/13b895f34745c4a0c624479173d3a04514f485fb/run_app.py#L429-L489
2. `/api/proxy` accepts caller-supplied `url`, headers and body, limits the target hostname to the existing provider allowlist, then performs the server-side POST. The allowlist is a useful SSRF boundary but is not caller authorization. Commit-fixed source: https://github.com/Reese-max/prompt-autoresearch/blob/13b895f34745c4a0c624479173d3a04514f485fb/run_app.py#L499-L547
3. `main()` uses `ThreadingTCPServer(("", PORT), LocalProxyHandler)`, i.e. wildcard-interface binding, while the user-facing console text says to open `http://localhost:8000`. Commit-fixed source: https://github.com/Reese-max/prompt-autoresearch/blob/13b895f34745c4a0c624479173d3a04514f485fb/run_app.py#L552-L565

Classification: `BUG / P1 / CONFIRMED / SOURCE_CONFIRMED / NEEDS_REVIEW / auto_implementation=false`.

Why P1, not P0: default source permits a network-reachable authorization gap for core mutating/cost-bearing actions whenever the host is reachable, but this audit did **not** establish actual Internet/LAN exposure of an owner machine, credential exfiltration, data loss, arbitrary-code execution, or a real unauthorized provider spend. No attack was executed. Network/firewall reachability remains UNKNOWN.

Minimum effective fix: bind the core UI server to `127.0.0.1` by default. If an owner-approved explicit external-bind mode must remain, require a small configured authorization token or equivalent local auth boundary for mutating routes and use a controlled Origin policy. Preserve the provider-host allowlist. Do not build OAuth/accounts/API gateway/database/general auth framework for this issue.
